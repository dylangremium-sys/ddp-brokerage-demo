# DDP Brokerage — public crawl policy
#
# WHY THIS FILE MUST EXIST AS A STATIC FILE
# vercel.json rewrites /((?!api/).*) -> /index.html. With no static file here,
# a request for /robots.txt did not 404 — it returned the SPA shell as
# 200 text/html, so crawlers received an HTML document where a directive file
# belongs. Vercel serves static files before rewrites (the same reason
# /favicon.svg resolves), so this file wins without any vercel.json change.
#
# SCOPE OF THE PUBLIC SEARCH SURFACE TODAY
# The application is state-routed, not URL-routed: src/lib/urlRouting.ts maps
# the paths that accept a cold load. Those are the landing page at /, the four
# public corporate pages (/about, /contact, /privacy, /terms), and /farmer.
#
# The corporate pages are the approved public surface and are listed in the
# sitemap. /farmer is farmer onboarding, not public corporate information, so it
# stays disallowed below.
#
# Note what that does and does not achieve. Disallow governs CRAWLING, not
# indexing, so an externally linked /farmer can still surface as a bare URL. The
# register at src/lib/publicPageMetadata.ts also marks it noindex — but a
# crawler that obeys the Disallow never fetches the page and therefore never
# reads that noindex. The noindex is defence in depth (crawlers that ignore
# robots.txt, and direct fetches), not the operative control. Genuine
# containment of onboarding and auth surfaces stays with the search-exposure
# programme, exactly as crawlPolicyFiles.test.ts already says.
#
# Assets are deliberately NOT disallowed. The landing page is client-rendered,
# so a crawler that cannot fetch /assets/*.js and /assets/*.css sees an empty
# document. Blocking them would hide the page it is trying to read.

User-agent: *
Disallow: /farmer
Disallow: /api/

Sitemap: https://www.ddpbrokerage.com/sitemap.xml
