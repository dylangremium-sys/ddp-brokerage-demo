# DDP Brokerage — public crawl policy
#
# WHY THIS FILE MUST EXIST AS A STATIC FILE
# vercel.json rewrites /((?!api/).*) -> /index.html. With no static file here,
# a request for /robots.txt did not 404 — it returned the SPA shell as
# 200 text/html, so crawlers received an HTML document where a directive file
# belongs. Vercel serves static files before rewrites (the same reason
# /favicon.svg resolves), so this file wins without any vercel.json change.
#
# SCOPE OF THE PUBLIC SEARCH SURFACE TODAY
# The application is state-routed, not URL-routed: src/lib/urlRouting.ts maps
# the paths that accept a cold load. Those are the landing page at /, the four
# public corporate pages (/about, /contact, /privacy, /terms), and /farmer.
#
# The corporate pages are the approved public surface and are the only entries
# in sitemap.xml.
#
# THIS FILE AND sitemap.xml NOW REACH THE OUTPUT BY DIFFERENT ROUTES.
# robots.txt is still hand-written here and copied to dist/ — it is prose and
# policy, and there is nothing to derive it from. sitemap.xml is no longer a
# file in this directory: it is GENERATED into dist/ by the same build step
# that writes the prerendered documents, from the same route list, so a URL
# cannot be advertised without a document existing to serve it. The Sitemap:
# line below is unchanged and still correct — the URL is what matters to a
# crawler, not which part of the build produced the bytes behind it.
#
# WHY /farmer IS DELIBERATELY *NOT* DISALLOWED HERE
# It used to be, and that was the bug. Disallow governs CRAWLING, not indexing:
# a compliant crawler that obeys `Disallow: /farmer` never FETCHES the page, and
# therefore never READS the noindex the page carries. The two controls did not
# compose — they stacked, and the weaker one won. Meanwhile an externally linked
# /farmer could still surface as a bare URL with no snippet, because nothing had
# ever told a search engine to exclude it in a way it could receive.
#
# So /farmer is now crawlable ON PURPOSE, precisely so that the exclusion can be
# delivered. It is excluded twice over, by two mechanisms a crawler can act on:
#
#   1. `X-Robots-Tag: noindex, nofollow` — an HTTP response header set for the
#      /farmer path in vercel.json. This is the authoritative control, and it
#      is unchanged. It does not depend on JavaScript running.
#   2. `<meta name="robots" content="noindex,nofollow">` — as defence in depth
#      for anything that reads the document rather than the response headers.
#
# NOTE, 2026-08-08: control 2 used to arrive only from JavaScript, because every
# path was served by the SPA rewrite as the same client-rendered document. That
# is no longer the case. scripts/prerender-public-routes.mjs writes a document
# per public route at build time, and /farmer gets one whose served bytes carry
# the noindex tag before any script runs. src/lib/publicPageMetadata.ts still
# injects it at runtime, so the two now agree rather than the second waiting on
# the first. This strengthens control 2; it does not demote control 1.
#
# Crawlable is NOT the same as indexable. /farmer must never appear in
# sitemap.xml, and publicPageMetadata.ts must keep it out of the approved set;
# both are asserted in crawlPolicyFiles.test.ts and publicPageMetadata.test.ts.
#
# /api/ stays disallowed. There is no exclusion directive to deliver there — it
# is not a page, and nothing should be reading it.
#
# Assets are deliberately NOT disallowed. The public documents now carry their
# own markup, so a crawler no longer needs /assets/*.js to read the words — but
# it still needs /assets/*.css to judge the layout, and Google treats a blocked
# stylesheet as a page it could not render properly. Blocking them would hide
# the page it is trying to read.

User-agent: *
Disallow: /api/

Sitemap: https://www.ddpbrokerage.com/sitemap.xml
